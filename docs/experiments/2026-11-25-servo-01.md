## 1. 시험 조건

방위각 신호는 `GPIO18`, 고도각 신호는 `GPIO19`에 연결하도록 안내했다. 서보 빨간색은 해당 독립 채널 +, 갈색은 −, ESP32는 USB로 전원을 공급하고 해당 채널 −와 공통 GND를 연결하는 구성이다. 두 채널 사용 시 독립 모드에서 음극만 공통 연결하도록 안내했다. 단독 시험은 다른 모터를 분리하는 조건이다. 안내 설정은 `6 V`, 채널별 전류 제한 최대 `3 A`, PWM(펄스 폭 변조) `50 Hz`, `attach` 범위 `1000–2000 μs`, 시리얼 `115200 bps`이다. `5 V` 비교도 제안했으나 수행 여부와 실제 공급 전압·전류 제한·CV/CC(정전압/정전류) 상태는 미확인이다. 모든 진단 단계에서 실제 배선과 설정이 같았는지도 미확인이다.

개발 PC 변경에 따라 Arduino IDE, Espressif ESP32 보드 패키지, ESP32Servo, ESP32 Dev Module 및 COM 포트 설정을 다시 안내했다. 프레임 제작 후 모터와 프레임의 결합을 분리하기 어려워 패널만 제거하여 비교했다. 패널은 기존 구상에서 `45 × 18 cm`, 약 `400 g`, 이번 진단 중 약 `300 g`으로 언급되었다. 이 수치는 사용자 제공 원문에 기록된 값이며 측정 방법과 프레임 포함 여부가 미확인이다. 확정된 치수·실측 질량으로 사용하지 않는다.

### 사용자 제공 시리얼 로그 발췌

날짜 및 스케치 버전은 미확인이다. 다음 수치는 명령값이며 실제 회전각·PWM 파형·전압·전류 실측값이 아니다.

```text
16:06:16.995 -> 1450
16:06:19.019 -> 1500
16:06:21.004 -> 1550
16:06:22.990 -> 1500
16:06:25.017 -> 1450
16:06:27.017 -> 1500
```

[원문 로그 파일](../../data/raw/2026-11-25-servo-01-serial.txt)은 위 여섯 줄의 시각 접두어·순서·값을 그대로 보존한다. 이전 대화의 사용자 메시지 `6e8feeff-9cc2-4838-9e13-bbfe8684fd8a` 및 이번에 제공한 Markdown 전문과 대조했다. 같은 메시지의 시험자 관찰은 “이렇게 뜨기만하고 안돌아가”이다. 원문에 날짜·시간대가 없어 임의로 추가하지 않으며 전체 세션 로그로 간주하지 않는다.

서보 전원을 연결하지 않아도 ESP32 USB 전원이 켜져 있으면 시리얼 명령 출력이 계속된다. 로그는 코드 실행의 근거이며 실제 서보 움직임의 근거가 아니다.

## 3. 재현용 진단 코드

기존 수동 위치 변경과 확대 스윕 조건을 조합한 예시이다. 실제 업로드 파일과 동일한 버전임을 확인하지 못했으며 이 예시 자체는 빌드·실물 시험하지 않았다. 자동 반복 대신 한 지점씩 수동 이동한다. 코드는 사용자가 제공한 Markdown 전문에 수록된 예시를 그대로 사용하고 언어 표기만 `cpp`로 정리했다. 외부 라이브러리 배포물은 복사하지 않는다.

```cpp
#include <ESP32Servo.h>
Servo motor;
const int SERVO_PIN = 19;
int pulse = 1500;
void setup() {
  Serial.begin(115200);
  motor.setPeriodHertz(50);
  Serial.println("T: start, + / -: 50 us step");
}
void loop() {
  if (!Serial.available()) return;
  char c = Serial.read();
  if (c == 'T' || c == 't') {
    if (!motor.attached()) {
      motor.attach(SERVO_PIN, 1000, 2000);
      motor.writeMicroseconds(pulse);
    }
  } else if ((c == '+' || c == '-') && motor.attached()) {
    int target = constrain(pulse + (c == '+' ? 50 : -50), 1300, 1700);
    while (pulse != target) {
      pulse += constrain(target - pulse, -5, 5);
      motor.writeMicroseconds(pulse);
      delay(30);
    }
  } else return;
  Serial.print("Target (us): ");
  Serial.println(pulse);
}
```

1. 전원을 끄고 패널을 안전하게 지지한 뒤 고도각 모터만 배선한다. 패널 미장착 상태에서 회전 간섭 및 배선 걸림을 확인한다.
2. Arduino IDE에서 보드·포트를 선택하고 스케치를 업로드한다. 시리얼 `115200 bps`로 설정한다.
3. 초기 `1500 μs` 이동이 안전한지 확인한 뒤 전원 인가 및 T 입력. 좁은 범위부터 +/−로 한 지점씩 이동하며 최대 3초 관찰한다. 필요하면 코드 범위와 목표 간격을 좁힌다. 코드는 관찰 시간을 자동 제한하거나 과부하를 차단하지 않는다.
4. 심한 떨림·간섭·높은 전류·전압 강하 발생 시 즉시 전원을 끈다. PWM 해제 시 패널이 떨어질 수 있으므로 안전 지지 없이 수행하지 않는다.
5. 전원을 끄고 패널을 장착한 뒤 동일한 안전 범위·접근 방향·배선·전압에서 비교한다. 넓은 범위부터 구동하지 않는다. `1300–1700 μs`는 제안 코드의 제한값이며 실제 하중에서 검증된 안전 범위가 아니다.

## 4. 관측 결론과 한계

**패널 제거 시 고도각 구동 정상, 패널 장착 시 심한 떨림이 관찰되었다. 최신 사용자 확인으로 프레임 무게에 눌리는 하중 조건과 이상 발생의 관련성을 확인했다.** 정량 반복 비교와 계측은 수행 근거가 없으며 축 눌림·마찰·변형의 세부 기전은 미확정이다.

| 원인 후보 | 확인할 사항 |
| --- | --- |
| 중력 토크·무게중심 불일치 | 회전부 전체 질량, 축에서 중심까지 거리, 하중 완화 비교 |
| 축 지지 부족·유격·프레임 탄성·축 눌림·마찰·변형 | 축 정렬, 지지 구조, 기구 간섭, 결합부 유격 및 하중 전후 변형. 직접 기전은 미확정이다. |
| 전원 불안정 | 모터 단자 전압, 전류, CV/CC 및 PWM 파형 |
| 내부 위치 피드백·기어 | 일정 명령에서도 진동 가능. 패널 제거 시 정상 작동은 하중 관련성을 지지하지만 개체 이상을 배제하지 않는다. |
| 방위각 미회전 | 고도각과 다른 모터의 증상이다. 전원·PWM·기구 간섭 및 최종 재시험이 필요하며 최종 원인은 미확정이다. |

고도각 최대 정적 중력 토크의 계산 예시는 `m g r`이다. 회전축에서 무게중심까지의 거리 `r`이 중력 방향과 수직일 때의 최대값이며, 예시로 `0.3 kg`, `0.09 m`, `g = 9.80665 m/s²`를 가정하면 약 `0.265 N·m`(`2.7 kgf·cm`)이다. 실측값이 아니며 프레임, 마찰, 관성은 제외했다. 정지 토크는 지속 사용 가능한 토크로 간주하지 않는다.

패널 제거·재장착 때 체결·배선·초기 위치가 함께 바뀌었는지는 미확인이다. 패널 제거는 프레임 하중 전체를 제거한 완전 무부하 모터 시험을 뜻하지 않는다. 하중 관련 관찰을 모든 전기적 원인의 배제나 방위각의 최종 원인 확정으로 일반화하지 않는다. 개선 후 실제 하중 안정성과 정량 계측은 미검증이다.

## 5. 후속 조치 및 M5 완료 기준

1. 회전부 질량·무게중심·회전축 위치 및 기구 치수·사진을 기록한다.
2. 회전축을 무게중심에 가깝게 조정하고 반대편 지지축·부싱·베어링, 결합부 보강 또는 균형추를 검토한다. 하중 지지와 회전 구동을 분리하는 방향으로 설계하며 균형추의 전체 축 하중 증가도 고려한다. 채택안·담당·완료일은 미정이다.
3. 실제 업로드 원본과 보드 패키지·라이브러리 버전을 보존한다. 모터 단자 전압, 전류, CV/CC, 실제 각도 및 진동을 기록하고 동일 조건에서 방위각을 재검증한다. 전원을 끈 상태에서 배선·채널·모터를 한 항목씩 교차 비교한다.
4. 안전 범위에서 패널 장착 후 두 축 단독·동시 구동과 자세 유지 반복 시험을 수행한다. 떨림·간섭·전원 이상이 없는 범위 및 보조 소비를 기록한다. 허용 각도 오차·진동, 유지 시간·반복 수, 전원·온도의 판정·중지 기준은 시험 전에 정하며 현재는 미정이다.
5. M5 실제 하중 검증 이후 LDR(조도 의존 저항) 자동 태양 추적 및 MPPT(최대전력점 추적) 통합을 진행한다.

후속 기록 열 제안: `run_id`, `axis`, `panel_attached`, `pulse_cmd_us`, `approach_direction`, `actual_angle_deg`, `servo_voltage_v`, `servo_current_a`, `supply_mode`, `vibration`, `hold_time_s`, `notes`. 미측정값은 미측정으로 표시한다. 새 시험은 실제 수행 날짜의 별도 ID로 기록하고 [검증 계획](validation-plan.md)의 데이터 규칙에 따라 원본과 처리 결과를 구분한다.

이 시험은 정성 진단으로 발전량·MPPT 성능·보조 소비 에너지 및 M5 전체 완료를 입증하지 않는다. 개선 후 실제 하중 자세 유지·반복 구동·이중축 동시 안정성은 미검증이다. 기존 11월 22일 실제 하중 검증 목표가 미완료인 영향과 M6 추적 조건 B·D의 선행 조건은 [개발 계획](../development-plan.md#m5-진행-상태와-다음-검증)에 기록한다.
